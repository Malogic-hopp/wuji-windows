# Tauri 2 + React 19 阶段 7A 完成说明

日期：2026-07-19

状态：已完成；独立 dev-preview 便携发布基线、self-contained Bridge/Agent、隔离目录、target-triple 命名和自动化布局门禁均已通过

实施分支：`codex/application-client-sdk`

## 1. 本阶段范围

阶段 7A 只建立 Tauri dev-preview 的独立发布与包布局基线：

- 不修改既有 `publish/scripts/publish.ps1` WPF 发布流程；
- 不启用 NSIS/MSI 安装器，不签名，不注册登录启动；
- 不切换默认 WPF Shell，不访问或修改 prod channel；
- 不修改 Bridge 合同、IPC、SQLite、Agent 状态机或数据格式；
- React 仍不能传入 executable、path、target triple 或 channel。

本阶段产物是供后续 installer、安全和完整验收使用的 portable dev-preview package，不是 production 候选包。

## 3. 独立发布脚本

新增：

```text
publish/scripts/publish-tauri.ps1
publish/scripts/test-tauri-package-layout.ps1
```

Tauri 项目增加入口：

```powershell
pnpm package:dev-preview
pnpm package:layout:check
```

`publish-tauri.ps1` 独立执行：

1. `dotnet publish` Bridge，`Release + win-x64 + self-contained=true`；
2. `dotnet publish` Agent，`Release + win-x64 + self-contained=true`；
3. `tauri build --no-bundle --target x86_64-pc-windows-msvc`；
4. 按合同组装隔离目录；
5. 生成带三个 executable SHA-256 的 `package-manifest.json`；
6. 自动运行 package layout gate。

脚本只清理由合同固定、且位于 `artifacts/tauri-dev-preview` 下的输出目录。它不调用或修改 WPF publish，不启动 Tauri、Bridge 或 Agent。

- Agent 固定在 Bridge 工作目录的 `Agent/` 下，复用现有 `WindowsAgentProcessController` 首选查找规则；
- Release Bridge apphost 文件名包含 Cargo target triple；
- Bridge `.deps.json`、`.runtimeconfig.json` 和 managed DLL 保留原程序集名称；
- 包内不包含 `QuantifiedSelf.Windows.App.exe`、PDB 或 WPF publish 输出。

Rust Release 路径由 `TAURI_ENV_TARGET_TRIPLE` 生成 Bridge 文件名；Debug 仍使用原有 `src-tauri/sidecars/bridge/QuantifiedSelf.Windows.Client.Bridge.exe`，不会破坏 `pnpm tauri dev`。

## 5. 自动化 package layout 门禁

`test-tauri-package-layout.ps1` 检查：

- package identity、version、dev channel、RID、target triple 与合同一致；
- packaged contract 与仓库合同 SHA-256 一致；
- Shell、Bridge、Agent executable 均存在；
- Tauri Shell PE Header 必须为 Windows GUI subsystem `2`，不得以 Console subsystem `3` 发布；
- Bridge/Agent self-contained runtime 文件完整；
- Bridge/Agent `.deps.json` 和 `.runtimeconfig.json` 完整；
- Bridge 使用唯一 target-triple apphost 名；
- Bridge、Agent 不得平铺到 App 根目录；
- Agent 不得平铺到 Bridge 根目录；
- 包内不得包含 WPF executable 或 PDB；
- manifest 中 Shell、Bridge、Agent SHA-256 与实际文件一致。

新增 5 项 `TauriPackageLayoutArchitectureTests`，静态冻结合同、脚本、目录隔离、self-contained 参数、npm 入口、Release Bridge 路径和 React 无 path/targetTriple 权限。

### 6.1 陈旧 Agent 状态恢复修复

GUI smoke 进一步暴露了一个真实恢复场景：上一次结束 `pnpm tauri dev` 时 UI 已退出，但 Agent 未经过显式 stop；随后旧 Agent 异常结束，dev runtime 文件仍保留 `Running`。portable GUI 冷启动后得到：

```text
actualState=stale
isRunning=false
isStale=true
```

旧 React 呈现只根据 `actualState=stale` 开放“停止”，没有结合 `isRunning`。因此页面显示“状态待确认”，用户只能执行对不存在进程无效的 stop；重新查询后 runtime 仍是 stale，看起来像按钮没有反应。托盘菜单也存在同类动作判定缺口。Agent、Named Pipe 和 package layout 本身没有缺失。

本次修复冻结以下语义：

- `stale/error + isRunning=false` 显示“记录已中断”，只允许重新启动；
- `stale/error + isRunning=true` 保留“状态待确认”，只允许停止；
- stale 且进程不存在时，不再把旧健康文件显示为“服务响应正常”；
- React 顶栏和 Rust 托盘使用一致的可用动作；
- Agent 命令成功后同时失效 Agent status 与 Dashboard overview query，避免启动、暂停、恢复或停止后页面仍显示旧摘要。

修复后重新执行 `pnpm package:dev-preview`，全部 package layout gate 再次通过。随后直接使用最终包内 target-triple Bridge 和 self-contained Agent 执行真实 dev 恢复 smoke：

```text
initial: actualState=stale, isRunning=false, isStale=true
agent.start: packaged Agent=1, dev Named Pipe=1
observe: actualState=running, Dashboard overview readable
heartbeat: 2026-07-19T04:22:12.1273414Z
        -> 2026-07-19T04:23:28.1257206Z
agent.stop: actualState=stopped
final: Agent=0, Bridge=0, dev Named Pipe=0
```

smoke 只使用固定 dev channel，没有删除旧 runtime 文件，也没有访问 prod channel；测试启动的 Agent 最终通过 Bridge 显式 stop 清理。
